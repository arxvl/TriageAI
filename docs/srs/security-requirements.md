# Security Requirements (SR)

**Project:** TriageAI: A Transformer-Based NLP System for Canine and Feline Symptom Triage and Clinical Decision Support
**Source:** SRS v1.1. IDs and the text in the Description column are authoritative: do not renumber, reword, or delete them. Priority follows the SRS keyword (`SHALL` = Must, `SHOULD` = Should, `MAY` = May).
**Sibling files:** [functional](functional-requirements.md) · [non-functional](non-functional-requirements.md) · [interface](interface-requirements.md) · [business rules](business-rules.md) · [database](database-requirements.md) · [security](security-requirements.md)

**Coverage:** SR-01 to SR-16, 16 requirements, no gaps.

Security behaviour is implemented per [ADR-11](../adr/ADR-11-cookie-sessions-rbac.md) (sessions and RBAC), [ADR-10](../adr/ADR-10-deidentification-fail-closed.md) (privacy boundary) and [ADR-13](../adr/ADR-13-docker-compose-single-vm.md) (transport, headers, backups). Each item is checked and signed off in `docs/security-review.md` before release.

| ID | Requirement | Description | Priority | Area | Acceptance criteria | Related |
|---|---|---|---|---|---|---|

| **SR-05** | Server-side RBAC | Role-based access control SHALL be enforced on the server for every API endpoint, not only in the user interface. | Must | Authorization | A route-scanning test proves every endpoint declares require_role; UI hiding is never the only control. | FR-59, BR-02, BR-05 |

## Notes

- **SR-10 (prompt injection) is a standing constraint on prompt authoring.** Owner text is always wrapped in delimiters, the prompt states that text inside them is data, and the output is validated against a schema. The model never receives database credentials or tool access.
- **SR-08 has a startup guard:** the application refuses to start with a real LLM provider and a mock de-identifier ([ADR-17](../adr/ADR-17-mock-first-stage-registry.md)).
- **SR-14** depends on open item TBD-11 (retention period). Agree the period with the adviser before the evaluation begins, then record it here.
- **SR-02** specifies Argon2id or bcrypt; the implementation uses Argon2id. Do not change the algorithm without updating this note and re-hashing on next login.
